00 Directive d'Exécution en Chambre Blanche & Contraintes

Lisez cette section en premier avant de créer tout fichier. Ce document est la source de vérité unique.

Instruction Système pour le LLM Implémenteur

Vous réalisez une implémentation en chambre blanche de AiDD (AI Driven Development), un framework de livraison logicielle piloté par IA, portable et sans serveur, ciblant GitHub Copilot (.github/ + .aidd/). Créez chaque fichier listé à la Section 01 dans l'ordre séquentiel (Tâche 0 → Phase 1 → Phase 2 → Phase 3 → Phase 4), puis exécutez la suite de vérification de la Section 08 jusqu'à obtenir le code de sortie 0 sur chaque contrôle.

Contraintes Non Négociables

  • IP 100 % Chambre Blanche : Utilisez exclusivement le nom AiDD (AI Driven Development) et une terminologie originale adaptée à l'entreprise (.aidd/, GPS/Navigator, Two-Hat Review, Story Packet). N'incluez aucune référence à des frameworks externes, méthodologies tierces ou droits d'auteur externes.
  • Zéro Runtime / Zéro Serveur : Ne créez et ne requérez aucun environnement Python, Node.js, paquet npm, démon en arrière-plan, base de données ou binaire CLI personnalisé.
  • État Lisible Nativement : Les fichiers d'état utilisent des tableaux Markdown simples et des lignes clé-valeur exactes afin que les LLM, bash POSIX et PowerShell Windows les lisent nativement sans parseur YAML/TOML.
  • Clonage des Références d'Or : Créez d'abord les trois fichiers de Référence d'Or de la Tâche 0 mot pour mot, puis clonez exactement leurs clés de frontmatter et leurs titres de section dans tous les autres agents et invites.

Problème Résolu & Capacités Clés

  • CAP-1 Installation Portable : Copiez .github/ et .aidd/ dans n'importe quel dépôt pour activer immédiatement la livraison structurée.
  • CAP-2 Routeur GPS/Navigator : Une commande en lecture seule inspecte l'état du dépôt et recommande exactement une prochaine étape sans ambiguïté.
  • CAP-3 Hybride 6 Agents + 6 Invites : Sépare les rôles métier (personas) des actions transverses (invites/compétences).
  • CAP-4 Bootstrap de Dépôt Existant : Détecte automatiquement la pile, les commandes de lint, typecheck et test dans .aidd/PROJECT_CONVENTIONS.md.
  • CAP-5 SDLC Double Voie : Voie complète (Brief → Spec → Architecture → Story Packets → Dev → Two-Hat Review) plus voie rapide /quick-fix.
  • CAP-6 Porte Qualité à 3 Couches : Séparation Two-Hat + Execution Evidence terminal brute + garde-fous déterministes pre-commit.sh & pre-commit.ps1.
  • CAP-7 Alignement Continu : /retrospective post-jalon et débat multi-personas /roundtable-panel.

## Deterministic Steps
1. **Vérifier le Bootstrap des Conventions :**
   - Vérifier que `.aidd/PROJECT_CONVENTIONS.md` existe et que sa ligne `- **Test Command:**` est renseignée (pas `<command or NONE>`).
   - Si absent ou non renseigné, recommander immédiatement `/repo-bootstrap` et s'arrêter.
2. **Vérifier la File des Stories Actives (`PROJECT_STATE.md`) :**
   - Inspecter les lignes de `.aidd/PROJECT_STATE.md` selon cet ordre de priorité strict :
     1. `IN_REVIEW` → recommander `/two-hat-review` (avec `@qa-reviewer`) sur ce Story Packet.
     2. `IN_PROGRESS` → recommander de poursuivre avec l'`Owner Persona` listé (typiquement `@developer`) sur ce Story Packet.
     3. `BLOCKED` → exposer le blocage et recommander `/roundtable-panel` ou le persona amont responsable.
     4. `READY` → recommander `@developer` sur le premier Story Packet `READY`.
3. **Vérifier l'Index de Planification Amont (`INDEX.md`) :**
   - Si aucune story active ne correspond à l'Étape 2, trouver la dernière ligne de `.aidd/INDEX.md` dont `Next Step` n'est ni `DONE` ni `-`.

4. **Vérifier l'État de l'Arbre de Travail :**
   - Exécuter `git status --short` (lecture seule) et mentionner toute modification non validée dans le résumé.
