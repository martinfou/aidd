# Companion: State Files, Contracts & Templates

## 1. Plain-Markdown State Files (`.ai-flow/`)
State files avoid complex YAML/TOML structures so both LLMs and `bash`/`PowerShell` parse them natively:
- **`.ai-flow/INDEX.md`**: Lightweight routing index mapping active briefs, specs, architecture docs, and stories with 1-sentence summaries.
- **`.ai-flow/PROJECT_STATE.md`**: Plain Markdown table tracking active work items (`ID | Title | Lane | Status | Owner | Artifact Path`).
- **`.ai-flow/PROJECT_CONVENTIONS.md`**: Generated by `repo-bootstrap`. Must include the exact machine-parseable line:
  ```markdown
  - **Test Command:** `<command or NONE>`
  ```
  Plus tech stack, lint/typecheck commands, branching/commit rules, and security guardrails.

## 2. GPS/Navigator Deterministic Decision Tree
1. If `.ai-flow/PROJECT_CONVENTIONS.md` is missing or unpopulated → recommend `/repo-bootstrap`.
2. Else read `.ai-flow/PROJECT_STATE.md` and prioritize: `IN_REVIEW` (→ `/two-hat-review`) > `IN_PROGRESS` (→ `developer`) > `READY` (→ `developer`).
3. Else inspect `next_step:` frontmatter on the latest artifact in `.ai-flow/work/`.
4. Output exactly one recommendation: **Next Action**, **Target File**, and **Why**.

## 3. Artifact Templates (`.ai-flow/templates/`)
All 4 templates include `next_step:` frontmatter and a compact top-of-file **Context Capsule / Handoff Summary**:
- `brief.md` (Stage 1)
- `spec.md` (Stage 2)
- `architecture.md` (Stage 3)
- `story-packet.md` (Stage 4): Self-contained packet inlining AC, architectural constraints, UX states, `lane: standard | quick-fix`, `status: READY | IN_PROGRESS | IN_REVIEW | DONE`, `## Execution Evidence`, and `## Review Verdict`.
