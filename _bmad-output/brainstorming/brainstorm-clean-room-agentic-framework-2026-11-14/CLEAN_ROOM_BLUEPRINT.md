# `.ai-flow/` — Clean-Room Serverless Agentic Delivery Blueprint (v1)

A zero-install, zero-server, pure-Markdown framework for AI-assisted software delivery in corporate repositories. It uses the filesystem as a state machine, separates **Personas** (role lenses) from **Skills** (cross-cutting actions), and enforces quality through a 3-layer deterministic gate.

---

## 1. Design Principles & v1 Scope

### Core Architecture
- **Serverless & Zero-Runtime:** No Node, Python, daemons, background servers, or custom CLIs. Everything runs through plain Markdown prompts, personas, and checklists.
- **Optional Native Scripts Only:** Deterministic checks (such as pre-commit guards) use standard `bash` (macOS/Linux) or `PowerShell` (Windows) only where deterministic enforcement is required.
- **Filesystem as State Machine:** Shared Markdown state files (`INDEX.md`, `PROJECT_STATE.md`, `PROJECT_CONVENTIONS.md`) and artifact frontmatter (`next_step`) drive workflow routing.
- **Hybrid Role + Action Model:**
  - **Core Personas (6):** Role-based lenses for domain ownership (`Analyst`, `PM`, `Architect`, `UX Designer`, `Developer`, `QA Reviewer`).
  - **Standalone Skills (6):** Cross-cutting, invocable actions (`GPS/Navigator`, `Repo Bootstrap`, `Quick-Fix`, `Two-Hat Review`, `Retrospective`, `Roundtable Panel`).
- **Streamlined Corporate Delivery Flow:**
  `Brief` → `Spec` → `Architecture` → `Story Packets` → `Implementation` → `Two-Hat Review` (with a `Quick-Fix` fast-track lane for small tickets).

### v1 Scope Boundaries
| Included (MUST) | Excluded (WON'T) |
| :--- | :--- |
| Portable `.ai-flow/` pure-Markdown folder | Background servers or daemons |
| `GPS/Navigator` state-inspecting router | Custom Python/Node CLI runtimes |
| 6 Core Personas | Complex YAML/TOML state parsers |
| 6 Standalone Skills (incl. `Repo Bootstrap` & `Quick-Fix`) | External database or SaaS state stores |
| Self-Contained Story Packets + Context Capsules | Monolithic all-in-one prompt files |
| `INDEX.md` + `PROJECT_STATE.md` plain Markdown tables | Unverified self-approval by builders |
| 3-Layer Quality Gate (`bash`/`PowerShell` pre-commit guard) | |

## 2. Portable Copilot-Native Folder Tree (`.github/` + `.ai-flow/`)

Drop `.github/` and `.ai-flow/` into the root of any corporate repository. Personas map directly to **Copilot Custom Agents** (`.github/agents/*.agent.md`), cross-cutting skills map to **Copilot Prompts / Skills** (`.github/prompts/*.prompt.md` & `.github/skills/*/SKILL.md`), and `.github/copilot-instructions.md` wires the global rules.

```text
.github/
├── copilot-instructions.md            # Always-on Copilot rules & pointer to .ai-flow/INDEX.md
├── agents/                            # 6 Core Copilot Custom Agents (Personas)
│   ├── analyst.agent.md               # Discovery, business requirements, domain research
│   ├── pm.agent.md                    # Product specification, scope, prioritization, acceptance
│   ├── architect.agent.md             # Technical design, boundaries, ADRs, constraints
│   ├── ux-designer.agent.md           # User flows, interaction specs, UI/accessibility states
│   ├── developer.agent.md             # Implementation, unit/integration tests, evidence capture
│   └── qa-reviewer.agent.md           # Independent verification, diff audit, gate sign-off
├── prompts/                           # 6 Standalone Copilot Slash Prompts
│   ├── gps-navigator.prompt.md        # Inspects repo state & recommends exact next step
│   ├── repo-bootstrap.prompt.md       # Fingerprints existing repo into PROJECT_CONVENTIONS.md
│   ├── quick-fix.prompt.md            # Fast-track lane for small bugfixes/chores
│   ├── two-hat-review.prompt.md       # Adversarial review comparing git diff + evidence vs AC
│   ├── retrospective.prompt.md        # Post-milestone review & convention updates
│   └── roundtable-panel.prompt.md     # Multi-persona structured debate for hard decisions
└── skills/                            # Optional Copilot Agent Skills (mirrored/shared specs)
    └── gps-navigator/SKILL.md

.ai-flow/
├── README.md                          # Quick-start guide and Copilot invocation cheat sheet
├── PROJECT_CONVENTIONS.md             # Generated by Repo Bootstrap (stack, CI, lint, test cmds)
├── INDEX.md                           # Lightweight routing index for GPS/Navigator
├── PROJECT_STATE.md                   # Plain Markdown table tracking active work & gates
│
├── templates/                         # Standardized Artifact Templates
│   ├── brief.md                       # Stage 1: Business Brief
│   ├── spec.md                        # Stage 2: Functional Specification
│   ├── architecture.md                # Stage 3: Technical Architecture & Constraints
│   └── story-packet.md                # Stage 4: Self-Contained Story Packet
│
├── work/                              # Active & Completed Delivery Artifacts
│   ├── briefs/
│   ├── specs/
│   ├── architecture/
│   └── stories/                       # e.g., STORY-101-auth-timeout.md
│
└── guards/                            # Layer 3 Deterministic Quality Gate
    ├── pre-commit.sh                  # POSIX bash pre-commit guard
    └── pre-commit.ps1                 # PowerShell pre-commit guard (Windows corporate devs)
```

## 3. The 6 Core Personas

Personas act as **hats/lenses** that define ownership, tone, and constraints. They do not duplicate workflow orchestration logic.

| Persona | File | Primary Ownership | Key Deliverables | Hard Boundary |
| :--- | :--- | :--- | :--- | :--- |
| **Analyst** | `personas/analyst.md` | Problem framing, stakeholder needs, existing system discovery | `work/briefs/*.md` | Does not prescribe technical implementation |
| **PM** | `personas/pm.md` | Scope, functional requirements, edge cases, acceptance criteria | `work/specs/*.md`, Story AC | Does not alter architectural boundaries |
| **Architect** | `personas/architect.md` | System boundaries, data contracts, security, tech constraints | `work/architecture/*.md`, Story Constraints | Does not write feature code during design |
| **UX Designer** | `personas/ux-designer.md` | User journeys, state transitions (empty/loading/error), accessibility | UX sections in Specs & Story Packets | Aligns to existing design system in `PROJECT_CONVENTIONS.md` |
| **Developer** | `personas/developer.md` | Code implementation, tests, capturing terminal evidence | Code changes + `## Execution Evidence` | **Cannot** mark a story `DONE` (Two-Hat Gate) |
| **QA Reviewer** | `personas/qa-reviewer.md` | Independent diff inspection, test re-execution, AC verification | `## Review Verdict` + status flip to `DONE` | **Cannot** edit feature code; rejects or approves only |

## 4. The 6 Standalone Skills

Skills are invocable verbs that operate on `.ai-flow/` state and repository files.

### 4.1 `GPS/Navigator` (`skills/gps-navigator.md`)
- **Purpose:** Solves workflow discovery without a CLI. Inspects `INDEX.md`, `PROJECT_STATE.md`, `PROJECT_CONVENTIONS.md`, and artifact frontmatter (`next_step`), plus `git status`.
- **Behavior:**
  1. Checks if `PROJECT_CONVENTIONS.md` exists; if missing, recommends `Repo Bootstrap`.
  2. Reads `PROJECT_STATE.md` for any item in `IN_REVIEW`, `IN_PROGRESS`, or `READY`.
  3. Reads the `next_step` frontmatter of the most recent active artifact.
  4. Outputs a single, unambiguous recommendation: the exact **Skill or Persona** to invoke next, the **Target File**, and **Why**.

### 4.2 `Repo Bootstrap` (`skills/repo-bootstrap.md`)
- **Purpose:** Onboards existing corporate repositories in one pass.
- **Behavior:**
  1. Scans package manifests, build files, CI configs, linters, and test runners.
  2. Writes `.ai-flow/PROJECT_CONVENTIONS.md` containing:
     - Tech stack & runtime versions
     - Exact build, lint, typecheck, and test commands
     - Branching, commit, and PR conventions
     - Security/compliance guardrails
  3. Initializes `INDEX.md` and `PROJECT_STATE.md` if absent.

### 4.3 `Quick-Fix` (`skills/quick-fix.md`)
- **Purpose:** Fast-track lane for small, low-risk tickets (typos, config tweaks, isolated bugfixes) that do not warrant full Brief → Spec → Arch stages.
- **Behavior:**
  1. Creates a lightweight Story Packet marked `lane: quick-fix` with concise AC and blast-radius check.
  2. Applies the fix as **Developer**, runs relevant tests, and logs **Execution Evidence**.
  3. Still enforces the **Two-Hat Review** (or explicit fast-track sign-off) and **Pre-Commit Guard** before marking `DONE`.

### 4.4 `Two-Hat Review` (`skills/two-hat-review.md`)
- **Purpose:** Enforces adversarial separation between Builder (`Developer`) and Verifier (`QA Reviewer`).
- **Behavior:**
  1. Switches persona context explicitly to **QA Reviewer**.
  2. Reads the Story Packet's **Acceptance Criteria** and **Architectural Constraints**.
  3. Inspects `git diff` against the target branch and verifies **Execution Evidence** (terminal output) is present and non-fabricated.
  4. Independently runs the test/lint commands listed in `PROJECT_CONVENTIONS.md`.
  5. Writes `## Review Verdict` (`APPROVED` or `CHANGES_REQUESTED`) and updates `PROJECT_STATE.md` to `DONE` only on `APPROVED`.

### 4.5 `Retrospective` (`skills/retrospective.md`)
- **Purpose:** Continuous improvement after a release, sprint, or major story.
- **Behavior:**
  1. Reviews completed Story Packets, review rejections, and `git log`.
  2. Captures what slowed delivery or caused rework.
  3. Proposes concrete updates to `PROJECT_CONVENTIONS.md` or `.ai-flow/skills/` checklists.

### 4.6 `Roundtable Panel` (`skills/roundtable-panel.md`)
- **Purpose:** Structured multi-perspective critique for ambiguous or high-risk decisions (e.g., build vs. buy, schema migration, API breaking change).
- **Behavior:**
  1. Convenes 3–4 relevant personas (e.g., `PM`, `Architect`, `UX Designer`, `QA Reviewer`).
  2. Each persona evaluates the proposal strictly through its own lens and lists risks/trade-offs.
  3. Synthesizes a single decision record with `next_step` frontmatter.

## 5. `INDEX.md` & `PROJECT_STATE.md` Format

Both files use **plain Markdown tables** so both LLMs and `bash`/`PowerShell` scripts can parse them reliably with `grep`/`awk` or `Select-String` without YAML/TOML dependencies.

### 5.1 `.ai-flow/INDEX.md` (Lightweight Routing Index)
Used by `GPS/Navigator` to locate artifacts without scanning the entire repository.

```markdown
# .ai-flow/ Artifact Index

| ID | Stage | Title | Path | Next Step |
| :--- | :--- | :--- | :--- | :--- |
| BRIEF-01 | Brief | Session Timeout Hardening | work/briefs/BRIEF-01-session-timeout.md | pm:spec |
| SPEC-01 | Spec | Session Timeout Spec | work/specs/SPEC-01-session-timeout.md | architect:design |
| ARCH-01 | Arch | Token Refresh & Expiry ADR | work/architecture/ARCH-01-token-expiry.md | pm:story-packet |
| STORY-101 | Story | Enforce 15m Idle Timeout | work/stories/STORY-101-idle-timeout.md | skill:two-hat-review |
```

### 5.2 `.ai-flow/PROJECT_STATE.md` (Execution & Gate Tracker)
Single source of truth for story lifecycle and pre-commit guard checks.

Allowed `Status` values: `BACKLOG` | `READY` | `IN_PROGRESS` | `IN_REVIEW` | `DONE` | `BLOCKED`

```markdown
# Project Delivery State

| Story ID | Lane | Title | Owner Persona | Reviewer | Status | Evidence Logged |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| STORY-101 | standard | Enforce 15m Idle Timeout | Developer | QA Reviewer | IN_REVIEW | YES |
| STORY-102 | quick-fix | Fix CSV Export Encoding | Developer | QA Reviewer | DONE | YES |
| STORY-103 | standard | Audit Log Retention Hook | Developer | - | READY | NO |
```

## 6. Self-Contained Story Packet Format

Each Story Packet (`work/stories/STORY-XXX-slug.md`) embeds a compact **Context Capsule** at the top and all **Acceptance Criteria + Architectural Constraints** inline, so the `Developer` and `QA Reviewer` never need to load the full upstream Brief, Spec, or Architecture docs.

```markdown
---
id: STORY-101
title: Enforce 15-Minute Idle Session Timeout
lane: standard                # standard | quick-fix
status: IN_REVIEW             # BACKLOG | READY | IN_PROGRESS | IN_REVIEW | DONE | BLOCKED
owner: developer
reviewer: qa-reviewer
next_step: skill:two-hat-review
---

# STORY-101: Enforce 15-Minute Idle Session Timeout

## Context Capsule (Handoff Summary)
- **Why:** Compliance requires idle web sessions to expire after 15 minutes.
- **Upstream:** Derived from `SPEC-01` and `ARCH-01`.
- **Key Decision:** Use sliding-window server timestamp check in auth middleware; do not store expiry in client `localStorage`.

## Acceptance Criteria
- [ ] **AC-1:** Requests with `last_activity > 15m` return HTTP `401` with error code `SESSION_IDLE_EXPIRED`.
- [ ] **AC-2:** Active requests within 15m refresh `last_activity` atomically.
- [ ] **AC-3:** Unit and integration tests cover boundary conditions (`14m59s` valid, `15m01s` expired).

## Architectural & UX Constraints (Inline)
- **Boundary:** Modify `src/middleware/session.ts` only; do not alter JWT signing keys.
- **UX State:** Frontend redirect to `/login?reason=timeout` on `SESSION_IDLE_EXPIRED`.
- **Conventions:** Follow error envelope in `PROJECT_CONVENTIONS.md`.

## Execution Evidence (Required Before IN_REVIEW)
> **Rule:** Developer must paste actual, unedited command output here.

```text
$ npm test -- session.spec.ts
PASS src/middleware/session.spec.ts (6 tests, 0 failures)
$ npm run lint
0 errors, 0 warnings
```

## Review Verdict (QA Reviewer Only)
- **Reviewer:** `qa-reviewer`
- **Decision:** `PENDING` <!-- APPROVED | CHANGES_REQUESTED -->
- **Diff & Test Notes:** _(Filled during Two-Hat Review)_
```

## 7. The 3-Layer Quality Gate

Quality is enforced across three independent layers so no single persona can silently bypass verification:

1. **Layer 1 — Two-Hat Builder / Reviewer Split:**
   - The `Developer` persona implements the Story Packet, runs tests, sets `status: IN_REVIEW`, and stops.
   - The `QA Reviewer` persona (via `Two-Hat Review`) is the **only** role permitted to set `status: DONE` after auditing `git diff` against inline Acceptance Criteria.
2. **Layer 2 — Evidence-First Terminal Output:**
   - Every Story Packet must contain real, pasted command output under `## Execution Evidence` (tests, linter, typecheck) before entering `IN_REVIEW`.
   - `PROJECT_STATE.md` tracks `Evidence Logged` (`YES`/`NO`).
3. **Layer 3 — Deterministic Pre-Commit Guard (`bash` / `PowerShell`):**
   - Blocks commits if any `DONE` story in `PROJECT_STATE.md` lacks `Evidence Logged = YES`, or if staged changes touch code while a story is marked `DONE` without a corresponding `APPROVED` verdict.

### 7.1 Pre-Commit Guard Pattern (`guards/pre-commit.sh`)

```bash
#!/usr/bin/env bash
set -euo pipefail

STATE_FILE=".ai-flow/PROJECT_STATE.md"

if [[ ! -f "$STATE_FILE" ]]; then
  exit 0
fi

# 1. Fail if any DONE story in PROJECT_STATE.md has Evidence Logged = NO
if grep -E '\|\s*DONE\s*\|\s*NO\s*\|' "$STATE_FILE" >/dev/null 2>&1; then
  echo "[ai-flow gate] ERROR: A story is marked DONE in $STATE_FILE without Execution Evidence (YES)."
  exit 1
fi

# 2. Verify every DONE story file contains both Execution Evidence and APPROVED verdict
while IFS='|' read -r _ story_id _ _ _ status _; do
  story_id=$(echo "$story_id" | xargs)
  status=$(echo "$status" | xargs)
  if [[ "$status" == "DONE" && -n "$story_id" ]]; then
    story_file=$(find .ai-flow/work/stories -maxdepth 1 -name "${story_id}*.md" | head -n 1)
    if [[ -z "$story_file" ]]; then
      echo "[ai-flow gate] ERROR: Missing story packet for DONE story: $story_id"
      exit 1
    fi
    if ! grep -q "## Execution Evidence" "$story_file" || ! grep -q "APPROVED" "$story_file"; then
      echo "[ai-flow gate] ERROR: $story_file is DONE but lacks Execution Evidence or APPROVED verdict."
      exit 1
    fi
  fi
done < <(grep -E '^\|' "$STATE_FILE" | tail -n +3)

echo "[ai-flow gate] Passed."
```

### 7.2 Pre-Commit Guard Pattern (`guards/pre-commit.ps1`)

```powershell
$ErrorActionPreference = "Stop"
$StateFile = ".ai-flow/PROJECT_STATE.md"

if (-not (Test-Path $StateFile)) { exit 0 }

$lines = Get-Content $StateFile | Where-Object { $_ -match '^\|' } | Select-Object -Skip 2

foreach ($line in $lines) {
    $cols = $line.Split('|') | ForEach-Object { $_.Trim() }
    if ($cols.Count -lt 8) { continue }
    $storyId = $cols[1]
    $status  = $cols[6]
    $evid    = $cols[7]

    if ($status -eq "DONE") {
        if ($evid -ne "YES") {
            Write-Error "[ai-flow gate] ERROR: $storyId is DONE in $StateFile without Evidence Logged = YES."
            exit 1
        }
        $storyFile = Get-ChildItem ".ai-flow/work/stories" -Filter "$storyId*.md" | Select-Object -First 1
        if (-not $storyFile) {
            Write-Error "[ai-flow gate] ERROR: Missing story packet for DONE story: $storyId"
            exit 1
        }
        $content = Get-Content $storyFile.FullName -Raw
        if ($content -notmatch "## Execution Evidence" -or $content -notmatch "APPROVED") {
            Write-Error "[ai-flow gate] ERROR: $($storyFile.Name) is DONE but lacks Execution Evidence or APPROVED verdict."
            exit 1
        }
    }
}

Write-Host "[ai-flow gate] Passed."
```
