- (direction) Ask questions one by one with multiple choice and a write-in option
- (technique) started First Principles Thinking
- (idea by coach) Filesystem as state machine: shared Markdown state files + persona lenses + checklist skills
- (insight) Hardest problem without a server/CLI is workflow discovery & routing (knowing what step/skill to run next)
- (idea by coach) Artifact frontmatter next_step + a single GPS/Navigator skill that inspects repo state and recommends the exact next skill
- (idea by user) Single Navigator/GPS skill inspects repo state and recommends the exact next command/persona to invoke
- (idea by coach) Skills as verbs vs personas as hats: either bundle persona inside each skill or keep them separate composable layers
- (idea by user) Hybrid architecture: Core roles (PM, Architect, Dev, QA) are personas; cross-cutting actions (review, retro, GPS) are standalone skills
- (technique) started Constraint Mapping
- (idea by coach) Zero-install portable folder (.ai/ or .agent/): pure Markdown skills+prompts+personas with zero Python/Node runtime dependencies
- (idea by user) Zero-runtime pure Markdown by default, with optional native bash/powershell only if deterministic checks are needed
- (idea by coach) Plain Markdown tables (e.g. PROJECT_STATE.md) or simple JSON instead of complex YAML/TOML parsers so LLM + bash/powershell can read natively
- (idea by user) Keep agile flow (Brief -> Spec -> Arch -> Stories -> Dev -> Review) but rename and streamline for corporate work
- (technique) started Morphological Analysis
- (idea by coach) Context Capsules: each stage writes a compact top-of-file Handoff Summary so downstream skills stay lean on tokens
- (decision) Handoff best practice: Self-contained Story Packets (all AC + arch constraints inline) paired with a lightweight INDEX.md for GPS routing
- (idea by coach) Adversarial Two-Hat Gate: Builder cannot mark a story Done; a separate Reviewer/QA skill must run tests and verify AC against git diff
- (idea by user) 3-layer Quality Gate: Two-Hat Builder/Reviewer split + Evidence-First terminal output in story + bash/powershell pre-commit guard
- (technique) started SCAMPER Method
- (idea by coach) SCAMPER Eliminate/Combine: collapse 9+ agile roles into 4 razor-sharp personas (Strategist, Architect, Builder, Verifier)
- (idea by user) Standard 6-persona roster: Analyst, PM, Architect, UX Designer, Developer, QA Reviewer
- (idea by coach) SCAMPER Reverse/Adapt: Bootstrap skill fingerprints existing corporate repo (stack, CI, style) into PROJECT_CONVENTIONS.md first
- (idea by user) Include both Repo Bootstrap (auto-detect stack/conventions) and a Quick-Fix fast-track lane for small tickets
- (decision by user) v1 MUST scope locked: portable pure-Markdown framework + GPS skill + 6 personas + Repo Bootstrap + Quick-Fix + Self-Contained Story Packets + 3-layer Quality Gate (incl bash/powershell pre-commit guard) + Retrospective & Roundtable Panel; WON'T: server/CLI/daemons
- (insight) Synthesis: Serverless pure-Markdown framework with optional bash/powershell guard, 6 core personas + standalone GPS/Review/Retro/Panel/Bootstrap/Quick-Fix skills, Self-Contained Story Packets + INDEX.md, and 3-layer Quality Gate
